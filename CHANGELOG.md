# Changelog

All notable changes to Agent Link for FreeCAD. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

- batch (fault 81b): a `gui_input` whose step opens a menu or dialog no longer ends its batch. Before, the batch was answered from inside the menu's loop with what ran so far, and the calls after the `gui_input` never ran. Now those calls run inside that loop, in order, each only while the menu or dialog is still open, and the batch is answered once with all results (`nested` in the answer). If it closes before a call (a `key: "Escape"` or `menu_item` call closed it), the loop is woken and the rest runs at the batch's own level after it. When the `gui_input` returns later, nothing runs again and no second answer goes out. Inside the loop a refused call stops the batch but undoes nothing (`rollbackNote`: a dialog's command can hold an open transaction); after the loop closed, rollback is as before. The budget and the batch record hold as before; `gui_input`'s own deadline is lifted while the batch works there, and the heartbeat marks the menu or dialog `working`, so the supervisor's watchdog does not close it as one that holds the call. live_run keeps its own replay (`gui_link.CONTINUE`).
- app_open (live 93): with the FreeCAD window closed by the person, nothing could open it again; the supervisor now starts it in the background (`open -g`: not in front, no focus) and waits up to 90 s for its link.

### Added

- Approvals through the client's own tool permissions (the owner, 18 Nov 2026; `agentlink/approvals.py`). Two small tools, always listed: `approve_file` (a Save, Don't Save or Replace press on a file dialog, a recovered copy saved over a file, `app_restart { save: "all" }`) and `approve_code` (cookbooks, macros, add-on install, update and removal, extensions). The person sets each in Claude Desktop ("Always allow", "Ask first", "Block"). The tools that need an approval never approve: they answer `pending` with the exact `approve` tool and arguments (name, source, version as a commit or a folder fingerprint, author), then act on the next call. Only a direct call from the client approves; a batch, a job, a cookbook, a lesson or a panel cannot. A new version needs a new approval. The FreeCAD window's Approve dialog (`agentlink/person_ok.py`) is an optional extra path (`Mod/AgentLink WindowApprove`).
- The critical-pressure guard (`agentlink/memguard.py`): the supervisor's watchdog reads macOS memory pressure every 3 s while a heavy job runs. At CRITICAL (two reads in a row) it stops that job only (its own child processes, or the job in FreeCAD's Python), and the answer says why with the checkpoint from before. Setting `Mod/AgentLink CriticalPressureGuard` (on by default).
- Cookbook format 2 (`agentlink/cookbook2.py`; `docs/design/porting-2026-11-18.md` part D): a data-only add-on port. Each entry has a level: 1 a function of the add-on, headless, with typed inputs (type, unit, limits, default; picks of faces, edges and objects); 2 a task panel filled from data, then OK; 3 a tree of data-only branches that gives the next entry; 4 the command through `cmd_run`; 5 not supported, with the exact blocker, tried again on each new add-on version. Preconditions, a result check, a probe field and a source field for each entry. Agent Link works out each entry's risk (none, file, code) from the call and a static scan of the add-on (`agentlink/addon_scan.py`: network, subprocess, dynamic or encoded code, secret files, environment, sys.path, file writes, other documents, settings); the scan's words go into the pending OK. Guards: calls resolve by import in the add-on's own package only (plain Python functions defined there; re-exports and sys.modules spoofs refused); inputs checked before the call; results filtered (~ paths, no keys or tokens, no other documents); injection-like words flagged. `port_scaffold` drafts format 2: IsActive to preconditions, typed public functions to level 1, task panel .ui files to level 2, refused commands to level 5; coverage bars in the answer. `cookbook_probe { name, entry? }` runs each level 1 entry once in a hidden scratch document and keeps the result apart from the file (the OK holds). `cookbook_run` takes `name` like the other cookbook tools (finding 75). Format 1 still runs. Live 95: level 1 drafts only API-like functions (docstring, typed arguments, document work, not glue, window code or plumbing); the rest is listed as `internal`. Live 96: the add-on scan is an index kept by the folder's fingerprint in `~/AgentLink/cookbook-scans/`, made at import; show and list read it. Cookbook names take - or _.
- Porting (`docs/design/porting-2026-11-18.md`; group `porting`, not lean). `guide_read { topic: "porting" }`: the hook file, the tool data, the STE rules, refusals, the core without `agentlink`, tests, privacy, cookbooks and a ready agent brief. `port_scaffold { folder }` (also `python3 -m agentlink.porting <folder>`): reads an installed add-on's files as text (never runs them), finds its `Gui.addCommand` names with `MenuText` and `ToolTip`, and writes a draft port (hook, tool data, core stubs, tests, lint, draft cookbook) in `~/AgentLink/ports/<name>/` only. Cookbooks (`agentlink/cookbook.py`): one file for each add-on in `~/AgentLink/cookbooks/`, each entry an STE description and a recipe (a FreeCAD command through `cmd_run`, a function of the add-on's package, or a list of calls through `batch`); `cookbook_list`, `cookbook_show`, `cookbook_import`, `cookbook_export`, `cookbook_approve`, `cookbook_unapprove`, `cookbook_run`. No entry runs before the person's typed OK, kept in the approved-macros store with the SHA-256 of the file and its script files; a change needs the OK again. Entries never take a tool's name; script files stay in their folder; scripts never call the OK, `batch` or `job_start`. No tool writes to the OK store or the cookbooks folder (`paths.check`).

- Usage log at the MCP layer (`agentlink/usage.py`; `docs/design/usage-log-2026-11-18.md`): each call's row in `~/AgentLink/usage/<day>.jsonl` also holds its job and step, the gap since the call before, its group, answer bytes and tokens, pictures, an error's reason, and marks for retries, tool searches, group switches, undos, rollbacks and background handoffs. A job row holds the versions and window or headless. A dialog row holds who answered it, how long it held the window and the calls it blocked. No argument values, file contents or geometry; paths become `~/…` or `<path>`. `usage_report { log: true }` gives the summary on request only.
- Progress in chat: the echo's status-bar words go to the client as `notifications/progress` when the request gives a `progressToken`. They add nothing to the answer.

- Jobs and restart (18 Nov; `docs/design/jobs-and-restart-2026-11-18.md`). Every call starts at once: no estimate refuses or holds a call (no prejudging; an export put at 2 min took 0.48 s). The supervisor answers any call with no answer after about 60 s (`AGENTLINK_DETACH_AFTER`) with a job id (`call-N`), keeps its real answer, and answers `job_status` at once, never behind FreeCAD (findings 41, 45). `job_start` runs its call where calls run; `wait: false` gives the id at once. The watchdog stops FreeCAD only when it is truly hung: no heartbeat and no CPU work (with its child processes) for a minute (`AGENTLINK_STALL`), or no heartbeat for 2 h. After `app_restart` or `agentlink_update`, calls wait for the first heartbeat of the new pid that pairs (macOS launch and quit notifications when pyobjc is there, the heartbeat's pid otherwise), up to 45 s each, then fail with clear words; never served headless without a word (finding 52); the agent's pinned document is its document again (finding 40). `doc_close { discard: true }` removes the window's modified mark first and sends `document_closing` to the add-ons, so FreeCAD's close confirm has nothing to ask; `dialog_answer` presses only Cancel on that dialog while a call closes the document (finding 62). `part_boolean` tries an invalid result again once with a small fuzzy value (finding 66).
- Fewer tokens in answers that are not needed (`agentlink/once.py`; measured in `docs/hardening/tokens-findings.md`): words that stand the same from call to call — a data tool's own note or use written in its entry, the health's advice on an overlap and on objects failing from before, the standing "still failing from before this call" part of a verdict, a sketch reading's DoF sentence, session_state's machine, a batch reply's own note — are given the first time in a conversation; after that the answer names their key in `saidBefore` (`health.saidBefore`), and `tool_groups { tool }` gives them again (`said`). A refusal is never shortened. A `batch { file }` answers from its record as `batch { to }` does (a line per call); `lines: "full"` gives the whole answer, and `batch { read, at }` reads any part of a record or to file back. The guide index names each section once (sectionTokens' keys).
- What a tool needs is read from the tool itself (`agentlink/needs.py`): `tool_groups { needs: tool, arguments? }` evaluates the entry's own leading checks — the `refuse` steps and the `let` steps they depend on, before its first step that changes the document — against the document as it is, without running the tool, and answers `{ applies: true | false | null, wouldRefuse [{ code, words }], notChecked [why] }`. Only helpers whose code only reads are ever called (`agentlink/data/readers.json`, derived by `scripts/tool_needs.py` and pinned by `tests/test_needs.py`); anything else is "not checked", never a guess. After each changing call a short `appliesNow` line (group names and counts) goes beside the health's `next` (`agentlink/appliesnow.py`; preference `AppliesNow`, budget `AppliesNowBudget` 150 ms); `tool_groups { now: true }` gives it in full and `tool_groups { find }` puts hits that would be refused now after the others. A meter records, per call, what the filter said and what happened (`applies_meter.json` in the session's folder; `usage_report`'s `appliesNow`). Advice only: nothing is hidden or blocked. `docs/data-tools.md` has the rule, the counts and the token costs.
- An installed add-on that fails to load is never silently absent (`agentlink/extstate.py`): every extension left out where the families load is noted with its error and kept in `~/AgentLink/extensions.json`; `session_state` carries `leftOut [{ extension, error }]` and a `warning` while it holds, `tool_groups` (no arguments) names the installed add-ons that brought no tools (`addonsWithoutTools`), the smoke test loads the installed add-ons' families and fails when one that loaded before no longer does (FreeCAD stays on the version before), and `agentlink_update` answers `leftOut`, `lostGroups` and a `warning` for any other one. Before, an add-on with a SyntaxError passed the smoke test, the update answered success, and its 133 tools were gone.
- A batch in the window runs faster from its fourth changing call (`agentlink/echo.py` `pace()`): the first three changing calls and the last are shown at the full pace, those between with a 60 ms pause and no settle paints — the workbench still comes up, the button lights and the result is selected. `EchoBatchDelay` (ms; 0 none, -1 the same as `EchoDelay`) sets it. A result's "lit for a moment" timer no longer clears a newer call's selection.
- The `next` hint names the likely next step, not the first five active tools by name: up to three tools, each with a few words on why, ranked from the document's own state by a table of rules (`agentlink/data/nexthint.json`, schema beside it; `agentlink/nexthint.py`) — a failing recompute, the selection, a sketch in edit and its DoF, a drawing page in front, an assembly's joints, how far the body is. A tool whose FreeCAD command on the active workbench's toolbars reports itself inactive is passed over; no other command is asked. `tool_groups { now: true }` puts the same picks first (`next`). An add-on adds rules for its own tools with `NEXT` on its family module.

- `batch` chains answers without sending them through the conversation (`agentlink/chain.py`): a call's `to: "file.json"` writes its whole answer to a file and leaves `{ written, keys | length }` in the reply; `{ "$file": path, "$at": "loops.0.points" }` and `{ "$from": call index, "$at": "bodies.0.name" }` anywhere in a later call's arguments are replaced as that call is about to run. A reference that cannot be followed refuses that call with what is there; 20 MB cap; paths checked as other tools' files are.
- `batch { build: "end" }` recomputes once for a run of `sketch_add`, `sketch_constrain`, `sketch_edit`, `sketch_offset` and `object_set` calls (`agentlink/hold.py`, by FreeCAD's own `Document.RecomputesFrozen`): held answers say `build: "held"` and leave out what only the rebuilt shape tells; `builds` carries the one health reading; a build that breaks a feature stops the batch as a refusal does. Other tools build first and run as before; an add-on declares its own safe tools with `hold.declare`.
- `guide_read`: the index gives each guide's and section's cost in approximate tokens, `start` (a `## Start here` map, added to the model, assembly and feature guides) and `later` (sections marked `<!-- later: when … -->` under their heading); `section` takes a list; `topic` takes a list and reads several guides up to about 55 000 characters, naming the rest in `next` (`agentlink/guideidx.py`).
- `tool_groups { find }` ranks with a tool index (`agentlink/data/tool_index.json`, generated by `scripts/tool_index.py` from the live echo's tables plus `scripts/tool_index_more.py`): each tool's FreeCAD workbench, the FreeCAD commands it does the work of and extra search words. Every word of a search counts, a workbench's name ("drawing", "techdraw", "mesh") lifts its tools, FreeCAD's own command names find the tool, and the one line of what a tool does is its description's first sentence. `now: true` answers the tools that fit the active workbench, an open sketch, the selection and FreeCAD's own active commands (the document's objects only without a window). `group: g` gives a line a tool; `tool:` takes up to 20 names. An add-on gives `workbench`, `commands` and `words` in its own tools.json entries.
- A family may declare `PINNED_FREE` (tool names answered after the person closed the document the agent worked in, as `doc_open` and `session_state` are), so the window link need not name an add-on's recovery tool; Agent Link's own list keeps it only until its add-on declares it.

### Removed

- The memory ceiling before a job (`MemoryCeilingGB`, "would need about N GB"): real pressure is watched instead.
- An add-on's `REPLACES` (and any `HIDES`): refused at load with a log line. An add-on never hides or replaces a hub tool or group.

## [0.3.0] - 2026-11-16

### Added

- `varset_new { name, properties: { size: "55 mm" } }` and `varset_set { varset, properties }` (group param): FreeCAD 1.0's variable sets (App::VarSet), each variable a property of its kind (a length, an angle, a number, true/false, text). `param_bind` takes `Dims.size` by the set's label or its name, and `param_list` lists the sets under `varsets`.
- `fea_setup { solid: n }` studies one solid of a multi-solid body alone (a hidden helper read again from the body at each solve).

- Release helpers (`scripts/release.py`): `check [--tag agentlink-vX.Y.Z]` reads every place the version is written (package.xml, pyproject.toml, server.json and its package, the server, `build_server`'s default, the extension's manifest, the newest changelog section) and the manifest's shape, and the extension's release job runs it against the tag before building; `fold X.Y.Z` moves Unreleased into the version's section (merging what came in after an earlier fold) and dates package.xml; `manifest` rewrites the extension's version and tools. `docs/RELEASING.md`: the steps that publish, for Agent Link and each add-on (tags, GitHub releases, PyPI, the MCP Registry, the FreeCAD Addon Index), each artefact through the privacy check first.
- The Claude extension's manifest names its icon and lists the tools served from the start (the lean groups and the launcher's `agentlink_update`, `tools_generated` since the list grows), and its version is Agent Link's (0.3.0; the copies released from ScanRuler's freecad-spike counted 0.4.x on their own). The README, SETUP and the Claude Desktop page link the file straight (`releases/latest/download/freecad-agentlink.mcpb`); the old ScanRuler channel is named only as retired.
- Long reads run as jobs (`agentlink/jobs.py`, new tools `job_status` and `job_start`): a read that is heavy, or took over 20 s here before, or any read given `background: true`, runs on a worker thread beside the call; within 45 s the call answers as before, past that it answers with a job id and `job_status { job, wait }` gives the answer when it is done. The job sits in the heavy queue's running list (session_state shows it), its time is logged so the next one of its size goes to a job at once, and changes to its document wait (refused, naming the job) while it reads it. Pictures, window tools and changes never run as jobs. A wall-thickness map of a 124k-triangle shell ran past a client's 80 s and its answer never came (M18 test drive, finding 19).
- `pd_mirrored`, `pd_linear_pattern` and `pd_polar_pattern` take `features: "all"`: the whole body, by FreeCAD 1.1's own transform-the-body mode where the feature has it (`TransformMode`), else every additive and subtractive feature up to the tip (M18 finding 32).

Agent Link's own study helpers are not parts.

- `live_run` always answers with its own steps and totals. A `gui_input` step that opens a dialog no longer ends the replay with a bare batch result: its answer goes to the replay, and the step's calls after it and the steps after it run inside the dialog's own loop (the step that answers the dialog runs); anything still open at the end is closed with `gui_unstick` and named in `leftOpen`. After a restart, a "(recovered …)" copy from an earlier restart that nobody changed is not recovered again, and one reopened anyway is closed (the heartbeat now says which documents are modified).

- `part_loft` lines its profiles up first: each closed profile runs the same way round along the loft (reversed where its winding disagrees) and starts at the point nearest the previous profile's start (a periodic B-spline re-parameterized there); `aligned` lists what changed. The result is checked: valid, closed, volume above 0 and no further than 15% beyond the profiles' joint box. A failed check gets OCC's shape fix, else the loft is refused with the reason (`profiles twist: start points or orientation differ`, `not closed: a profile is an open edge`). A solid loft through an open profile is refused before it runs. `ruled` stays.
- "sound" means valid, closed and a volume above 0 wherever a tool reports it (`geometry.soundness`, also `body_check`): an inside-out solid with a negative volume had been reported sound.
- `part_boolean` refuses a tool that is not a sound solid (invalid, open or inside out), an invalid result, and a fuse that dropped a tool (the tool reaches outside the base's box, but the result does not hold it); the tools are kept. It had returned the base unchanged and listed the tool as removed.
- A heavy Part boolean no longer gets FreeCAD stopped by the watchdog. Booleans, `body_check` and `history_undo`/`redo` are sized (`keep.SIZED`: a boolean by base faces x tool faces, the others by the document's faces) and estimated (their past runs here, else a rough rule). A boolean estimated over 60 s is asked about first in the window (the same call again runs it). A sized call estimated over 10 s writes `~/AgentLink/heavy-call.json` while it runs, and the supervisor's watchdog gives the call in hand its estimate times three (`keep.heavy_call_limit`), in the window and in the hidden FreeCAD. They are not queued.
- `show { objects }` shows or hides the objects it finds and lists the rest as `unknown`; only a call where none is found is refused.
- After a watchdog restart only the documents open at the restart come back: the newest heartbeat of the FreeCAD that was stopped (not one kept from an earlier call), `hidden.json` only when the FreeCAD that died wrote it, and old recovered copies the new window opened from temporary folders closed again (left open, and said, when they have changes).
- `object_set`'s `Placement` takes FreeCAD's own key names (`Base`, `Axis`, `Angle`, `Rotation` as `{ axis, angle }` or a quaternion) as well as `at`, `axis`, `angle`, in any case; a key left out keeps its value (a move keeps the turn), and an unknown key is refused with the keys it takes. `{ Base, Axis, Angle }` had been read as nothing given and reported a set that changed nothing. Every set whose value did not change is now marked `unchanged`, with a warning.
- TechDraw's wait for a view's lines pumps Qt's loop through `td_wait.pump`: an error raised there by someone else's timer or slot (PySide2 hands it to the caller) is logged and kept in `td_wait.PUMP_ERRORS`, never the TechDraw call's own failure. The overlay and the window-event watcher check that the window is up before importing FreeCADGui, so a headless FreeCAD no longer gets a windowless FreeCADGui loaded by a probe.

- ISO 286 fits no longer import TechDraw's tools in a FreeCAD without its window: the import failed half way and left FreeCADGui (without `getMainWindow` or `addCommand`) in `sys.modules`, so a later `td_view` in the same headless FreeCAD failed. Agent Link's own table answers there, as it did when the import failed.
- A `gui_input` click on a toolbar dropdown's ▾ arrow that opens a menu reports the button that menu belongs to (its `menu()`, its default action's menu, or an action group's default action among the menu's items), not the button to its left: on FreeCAD 1.1.3 New Sketch's arrow was reported as New Body. Without a menu, the arrow goes to the button whose rect holds it or the one immediately left of it, by global rects.
- CI: Workshop for FreeCAD is one add-on now (its packages at the top of its repository), so its folder itself goes on the path; the old per-part folders left gen_part, part_spec, the wall map and mass_properties out. test_gui_saved no longer leaves its stand-in FreeCADGui in sys.modules (every later test took it for the window), the overlay test's stand-in maps a QPoint where PySide imports, and gui_input's description is back under 1500 characters.

### Changed

- `import_file` brings every mesh file (STL, OBJ, PLY, 3MF …) in as a mesh (`Mesh::Feature`), whatever its size, unless `solid: true` asks for a body of its triangles (up to 200000); the answer's note says so. It had turned closed meshes of up to 20000 triangles into bodies on its own, so one STL came in as a body and the next, larger one as a mesh.
- `tool_groups { group }` answers with that group alone (its whole about and its tools), and `detail: true` gives every group's whole about without tool names; an unknown group is refused with the groups there are. A filtered call had answered with the whole catalogue of every group (6 to 9k tokens).
- `object_set` recomputes the object it set and what is built from it, not the whole document; `import_file` recomputes what it brought in. The steps' snapshot keeps each body's numbers while its shape is the same one (by the shape's hash), so a call no longer measures again bodies it did not touch. A call beside a heavy object it does not touch stays fast (a hidden 3.1M-triangle mesh had made each call take about 33 s on the Mac).
- Packaging for the first release: `agentlink-freecad --version` and `--help` answer without looking for FreeCAD; the build needs setuptools 77 or later (the licence expression and `license-files`, PEP 639); the package's classifiers and Documentation and Changelog links; the README's links are absolute, so they work on PyPI and in the Addon Manager. The release test checks `server.json` (the MCP Registry entry) against the package, its version and the README's `mcp-name` line. The Claude extension's icon (`packaging/mcpb/icon.png`, the workbench icon at 512 px).
- The overlay counts a button as covered only when the window's widget under its middle is another one (`childAt`, which passes over the overlay and its callout): an empty `visibleRegion` alone had reported plainly visible toolbar buttons as covered on the Mac (FreeCAD 1.1.3).
- `gui_input`'s `{item: {text}}` target, where several rows match (two open documents each with a Sketch), takes the active document's row first, then a row that shows now (its branch unfolded, inside the view) before one that must be unfolded or scrolled to; the hit says which (`document`, `under`, `matches`). It had clicked a folded row of another document, unfolding it off screen. From the live Tutor run on the Mac (FreeCAD 1.1.3).

From the live check on the Mac (FreeCAD 1.1.3).
- `fea_solve` solves through FreeCAD's own FEM: the study becomes an analysis (`<body> strength (fea_solve)`, replaced on each solve) with FEM's CalculiX solver, Gmsh mesh, material and fixed / force / pressure / self-weight constraints, meshed by FEM's Gmsh tools, run by FemToolsCcx, its results loaded into the analysis for the FEM workbench.
