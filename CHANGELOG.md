# Changelog

All notable changes to Agent Link for FreeCAD. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]
- A partly loaded document (FreeCAD opened it only for a link in another document; `Document.Partial`) refuses every changing call and `doc_save`, with the way out (`doc_revert` loads the whole file). Before, the change and the save said ok and FreeCAD kept nothing.
- `param_bind` refuses a target through a link property (`Body.Tip.Length`): FreeCAD keeps that expression on the Body and applies it to each new Tip. The refusal names the feature to bind instead.
- Modelling-practice warning "thread not made": a blind hole is now found by the material on the hole's axis (a line from the sketch's circle centre, cut with the shape before the hole), not by the body's box. When that cannot be read, the warning says only "modelled".

- One file for each part (branch `steering`, 21 Nov): `link_make` links an object of another .FCStd (FreeCAD XLink): `to: "Doc#Object"`, or `file` (relative: in the session's folder) with `to`. A file that is not open opens in the background; the agent's document stays active. It refuses an unsaved other document ("doc_save it first"). The answer adds `file`, `relative` and a `check` note (FreeCAD issue 33468: save, open again, read the target). `doc_save` names link paths in the saved file that find no file (`linkWarning`). `asm_joint` reads an LCS of a linked part from the linked file, not an object of the same name in the assembly's file. Guides `design` and `assembly`: the route for parts in their own files.

- Modelling-practice warnings (branch `steering`, 21 Nov; `agentlink/practice.py`, tests/test_practice_warnings.py): the health reading of a changing call gets `practice`, advice that is never red and never refuses. It names a Body of mostly primitives (3 or more, over half of its solid features), a boolean chain over 3 deep (Part booleans by their links, PartDesign Booleans in one body, or `part_boolean` results that kept one label in this conversation), Refine on in a weldment (4 or more tube members, or a fusing PartDesign Boolean), over 8 bodies in one file (with an assembly, or no other file open), and a modelled thread (and a thread that is not made: Reversed, or a blind depth). Each is said once for each document, object and kind, and again when it comes back. Nothing is added when nothing fires. `body_check` gives the same list as `practice` for its body. The Refine todo counts the bodies a PartDesign Boolean fuses as tube members too (one rule, `fusehint.members`).
- Steering toward FreeCAD's own modelling practice (branch `steering`, 21 Nov): guide `design` gets the section "Modelling principles" (one file per part and a thin skeleton; stable references; sizes from parameters; real features and patterns; a stand-in is a block, a part is designed; a short ordered tree; heavy detail cosmetic or last) and FreeCAD 1.1 traps (cross-file values need the file open; threads not in the hole tables, such as 9/16"-20; modelThread limits; 1.1 datums). Skill `design-kickoff`: the rule in one line and a pointer. A "Prefer" line on 20 tool cards (primitives, booleans, Placement, pipes, datums, patterns, hole, fillet, refine, attach, links, doc_new, bodies). Next hints: after a pad or pocket, the next sketch, holes and patterns come before fillets; after a primitive, a sketch and a pad.

- Guide `design` and skill `design-kickoff`: a part-by-part design pass after L2; a fix that changes a part's concept is a trade-off for the person; traps for Refine on weldments and lost binder edges.

- Bicycle L5 build of 21 Nov (FreeCAD 1.1.3, about 35 bodies, 32 assembly parts), findings 1 to 5 (tests/test_bicycle_l5_1121.py):

  - `sketch_attach` (3): `edge: "Binder.Edge1"` with `mode` (NormalToEdge by default, Frenet modes, Concentric, RevolutionSection) and `at` (0 to 1) hangs a sketch on an edge in place, also when a feature is built from it. `repair: true` points each element of the support at the element of the same number on the same object (a "missing element reference" after a change). Guide `design`, weldment: the trap.
  - Latency (5): a recompute after a call left in the assembly that holds the changed part, and FreeCAD's assembly solves on each recompute. `recompute_scoped` and the shared finish now leave out an assembly whose joint ends read nothing that the call recomputes (every end on an LCS that was not recomputed, or on another part), and clear its touch mark. The hub's other per-call work was already bounded or cached (health mark keys by shape hash, the snapshot's stats cache, the health budget).

## [1.0.0] - 2026-11-20

- New guide `design` and the optional skill `skills/design-kickoff/SKILL.md`: the design-engineering method for a new design (brief, concepts, levels and gates, hand-off, feedback loop), with the Agent Link steps for each part of it.
- `asm_joint` after the bicycle test drive of 20 Nov (a Part boolean on a part broke the joints on its faces; tests/test_asm_datum_repick.py):
  - A joint end can be a datum inside the part: an LCS, a datum plane, line or point (element: its name or label, a dotted path such as "Body.LCS", or `{ part, datum }`). The reference is `[part, ["LCS.", "LCS."]]`, as FreeCAD 1.1's Assembly stores a whole datum (an empty element). The joint sits on the datum's origin, along its z axis. A boolean or an edit does not rename a datum, so the joint stays on. The card says: put joints on LCS markers, not on faces that a boolean makes. `asm_list` and the answer name the end as Part.LCS by labels.
  - An end picked by a query keeps the query on the joint (property `AgentLinkQuery`, JSON; the answer's `queryKept`), with where the element was and the part's frame. After every changing call the health check reads these ends. When the element is gone (FreeCAD marks it "?") or is another element now, the query runs again on the part as it is, and the joint is pointed at what it finds ("re-picked Face12 -> Face15"); then the solver's line follows. When the query finds nothing, or two equal matches, the joint stays broken and the line says why. A part that the solver moves takes its query along; a Part boolean, which puts the shape in document coordinates, does not move it.
  - The card is shorter to keep it under the one-card bound of 900 tokens (with the bicycle drive's keep, autoFlip and chain words); `gap` has no schema words of its own (the card says them). The data tests: `tests/_meant.py` has the meant description, schema, answer field (`queryKept`) and the new trace lines (`TRACE_ADDED`). `scripts/ste_originals.json`, `agentlink/data/readers.json`, the readers pin and the stats are regenerated.
- Bicycle test drive of 20 Nov, the hub's findings (tests/test_findings_1120b.py):
  - `doc_switch` and `session_state` (2): after a restart, the agent's document and the document in front can differ. `doc_switch` to the agent's own document then binds the session again, sets FreeCAD's active document and, in the window, brings its tab to the front (`rebound: true`; the note names the document that was in front). It also rebinds when the session holds a closed document object of the same name. `session_state` gives `agentDocument`, `frontDocument` and `mismatch` while they differ (`docstates.front_document`, `docstates.mismatch`).
  - `fea_solve` and the other FEA runs (9): a Gmsh or CalculiX failure gives the solver's own error lines, not Gmsh's summary ("2 errors", "Check the full log"). It says where: the Gmsh surface, curve or volume number with the FreeCAD name of the same number (surface 12 is Face12), the points Gmsh names, and CalculiX's element (with its place) and node numbers. The whole log is kept as `gmsh.log` or `ccx.log` in the run folder, and the refusal gives its path (`ccx_io.gmsh_report`, `ccx_report`, `keep_log`).
  - `part_refine` (10): a refine, or fix and refine, that makes the shape worse changes nothing and says why: a valid shape that becomes invalid, fewer closed solids, or a volume change over 0.01 % (`geometry.refine_harm`). On a PartDesign Body, Refine of the tip is set back.
  - A copy keeps its material (11): `part_transform` (copy, mirror, scale), `object_duplicate` and `draft_clone` give the copy the material record of the original (`material.carry`; the source is kept as `materialFrom`). A body without a record takes the material of what it was copied from, a Draft clone's or a link's object, or the library card on its ShapeMaterial (`material.resolve`). `fea_setup`'s `material.from` and `materialNote` say which material it took and from where.
- Test drive of 20 Nov, the bicycle assembly (tests/test_bicycle_1120.py):
  - `asm_joint keep: true` (3): for parts already in position. The tool finds the joint's offset (place and turn about the joint) that holds them where they stand, so the solve moves nothing. It tries each side FreeCAD can put the offset on and keeps the one that moves nothing (else the least). Answer `kept { property, at, axis, angle, moved { mm, degrees } }`; `keepWarning` when the parts still moved. Not with `offset`, `rotate`, `gap`, `reverse` or `autoFlip`.
  - `asm_joint` flips (4): the tool does not turn a part over by itself any more. Parts that overlap after the solve get a warning that names each pair and its volume and tells how to flip (`reverse: true`, or `autoFlip: true`). `autoFlip: true` is the old way; then `flipWarning` and `crossedPlane` name each part whose centre the flip put on the other side of the joint's plane (the chainring on the wrong side).
  - `asm_joint kind chain` (5): FreeCAD's belt joint with the ratio `teeth1 / teeth2` (50 / 16 = 3.125). The teeth are given, or read from a PartDesign Sprocket (`NumberOfTeeth`) in each part; two sprockets in one part ask for the number. The radii are teeth x pitch / 2 pi (`pitch`, the chain pitch, 12.7 mm), so `asm_sweep` drives the cog by the teeth's ratio. `gears` and `belt` take `teeth1`, `teeth2` too. Answer `ratio`, `ratioFrom`, `teeth`. The echo lights Assembly_CreateJointBelt.
  - `asm_sweep` in time (6): the sweep checks the time before each step and between pairs of parts, and stops before 60 s (`SWEEP_BUDGET`). It answers the steps done with `partial: true`, `stepsDone`, `continueWith { joint, from, to, steps }` and `partialNote`; every part is put back. No step done: `verdict` "not checked".
  - `asm_sweep` static overlaps (7): an overlap there at the first step with the same volume at every step (0.01 mm³ or 1 %) is static. `staticOverlaps` lists it with its volume; `steps`, `verdict`, `collidesAt` and `clearFromStart` use only the contacts the motion makes.
  - The data tests: meant description, schema and answer changes in `tests/_meant.py`; new refusals in `UNREACHED`; three asm cases follow the new default (`autoFlip` in "turned over to stop an overlap").
- Skeleton workflow of the design kickoff (parameters, a master sketch, a SubShapeBinder in each Body, datums on the binder, Assembly joints on them; tests/test_datum_skeleton.py):
  - `pd_datum` and `part_datum` take `refs`: one to four references of any object in order (a sketch, a binder, a datum, an LCS, a feature: "Binder.Vertex3", "Skeleton.Edge2", a whole "Skeleton"), with `mode` (a FreeCAD MapMode) or a default from FreeCAD 1.1's attacher table: one vertex gives Translate; a vertex and an edge give OZX (origin at the vertex, Z along the edge; the vertex goes first); two or three vertices give OZX; a vertex and a circle give Concentric. A line or point datum has its own defaults (TwoPointLine, AxisOfCurvature, Vertex, CenterOfMass). With no plain default the tool asks for `mode`.
  - `offset { at, rotate }` sets the AttachmentOffset. `param_bind` on a nested path (`LCS.AttachmentOffset.Base.x`, `Placement.Rotation.Angle`) now answers the value at that path (it answered null).
  - `part_datum` takes `body` (a PartDesign Body) or `part` (an App::Part) to hold the datum.
  - `pd_datum kind: lcs` makes a `Part::LocalCoordinateSystem` (an App::LocalCoordinateSystem: a Body takes it in 1.1, and Assembly joints read its origin, axes and planes); `PartDesign::CoordinateSystem` (still in 1.1, made by PartDesign's own command) only where that type is not there.
  - The answer gives the datum, `refs` as kept, `mode`, `offset` and `world` (its placement in the document's coordinates).
- `show` and the session's body lookup find a PartDesign Body by its Label or Name, shown or hidden: an exact name before one that differs in case, a Body before other objects of that label, and a Body with an empty Shape gives its tip (test drive of 20 Nov, finding 13: hidden sprocket bodies were not found by the body's label).

- Test drive of 20 Nov and the README screenshot pass of 19 Nov, the hub's findings (tests/test_findings_1120.py):
  - `object_delete` (1): a container that only holds the object is not a user. A Body, an App::Part or a group in the object's InList does not stop the delete. So an unused sketch or the tip feature of a Body deletes without `force`. The object is first taken out of its container, so the Body's tip moves back. A real user (the pad on a sketch, the next feature) is still named and refused.
  - `asm_joint` (2, 3): new input `gap`, mm between the two joined faces after the solve (positive apart, negative overlap). The tool finds the offset for it, whichever way FreeCAD's offset runs for the two parts; `gap` and `offset` together are refused. The answer always gives `gap` where it can be measured (a flat face, or a round edge on a flat face, on a or b) and `at`: each element's centre when picked, in document coordinates. A query's `near` is in document coordinates (the card says so); `nearLocal` takes the point in the part's own frame.
  - `view_render` maps (4): the map's own reading has until 40 s into the call (`render.map_budget`). The stress and heat maps blend on the distinct points only, time the blend on a probe first, and thin the map before the blend when it would take longer (`render.blend_fit`); `detailCapped` says so, with the nodes and the time. `time.map` gives the map's seconds, `expected` includes them, and the logged work counts them in the drawing's units.
  - `view_render` meshes (6): shown meshes (Mesh::Feature, for example a texture result or an imported STL) are drawn, and a named one too. There is no map on a mesh. A mesh that an add-on already draws as its own layer is not drawn twice.
  - Saw-tooth edges on a map (screenshot pass 1): `render.subdivide` now halves each triangle's longest edge (by edge length, not by count). A long thin triangle becomes a row of small ones, so the wall map's long side faces are split evenly at the default detail. `render.even_length` follows that split (`SPLIT_AREA`).
  - One material list (9): `material_set` takes `measure_mass`'s short ids (steel, stainless, aluminium, brass …). It sets the first FreeCAD library card of a short list for the id (steel: Steel-Generic, then Steel-1C22 …), else Agent Link's stock figures; `mapped` says which. `measure_mass` already took `material_set`'s ids and card names.
  - `asm_bom` mass (11): a part in a print setup gets the printed estimate (walls and infill) of an installed add-on that owns mass, with `massAs` and `solidMass`. Without one, `massAs` marks the mass as solid, not as printed; `massNote` says that `slice` gives the slicer's figure. A part whose material is a library card, a stock id or a custom material now has a mass too (only filament keys had one).

- Every tool is listed with its own group, so enabling a group lists only what it says: `surface_loft`, `surface_points`, `surface_thicken`, `surface_fill` and `surface_polynomial` in surface, `draft_fix` in draft, `asm_rigid_group` and `asm_new_part` in assembly, `scad_tidy` in openscad, `points_structure` in points, `robot_tool` in robot, `sheet_cells` in sheet, `pd_shaft` in feature. `export` (every format) is in core; `export_file` stays callable as an unlisted alias. - Read-only calls no longer switch FreeCAD's workbench: only a call that changes the document (its tool's `changes` flag, so a changing tool's read action counts as a read) or a read an add-on declares as opening a panel (`OPENS` on its family) brings its bench up and lights a button; reads show in the Activity list (and, for those that show something, the caption and selection) and leave the bench where the person has it.
- The Activity tab reads for a layman: Did is a short plain sentence of what each call did, written per tool from its arguments ("Clicked Pin a Note, clicked the part, took a picture of the window", "Answered the Note dialog: OK", "Saved WindowTest", "Closed WindowTest (not saved)", "Set Pad Length to 24 mm", "Ran Isometric", "Switched to Part Design", "Read the reverse guide"), and Result a short outcome ("Pad made, 24000 mm³", "Saved as WindowTest.FCStd", "Refused: …"), never raw arguments, brackets, `note:`/`path:` keys or a folder: a path shows as its file name and a home folder never shows (`agentlink/activity.py`). The words are data, `agentlink/data/activity.json` (tool → `did` and `result` templates, the first whose fields the call gives); a tool not in it gets its friendly name and main argument. An add-on gives its tools' words with an `activity` template in its `tools.json` entry or `PHRASES` on its family. Lines are cut at the right end, the tooltip has the whole line and the call as sent (paths cut too); Time fits its contents, Did stretches, Result keeps 38% of the width after it, with no sideways scroll bar in a 355 px dock. The caption over the 3D view and the status bar use the same words.
- The panel in a narrow dock: the Activity tab's check box reads "Agent's steps", its lines are cut with the whole line in a tooltip; every Did name has one form, "Area › What" from the declared areas ("Window › Input", "Report › Read", "Document › Save"); "Save as Macro…" in Title Case; a step's line leaves out its type where the label is the same ("Step 1 of 1 — Pad (Length 20.00 mm): …").
- The supervisor's restart after a hang or crash answers and forgets only the calls in hand at that moment (a call sent right after the answer went to the fresh FreeCAD and was dropped from the watchdog's view, so it could wait for ever), and the watchdog leaves the dead child's call alone while the restart and recovery run (a slow recovery was counted as a second hang and the fresh FreeCAD stopped mid-recovery).

- Agent Link has its own repository (it began in ScanRuler's `freecad-spike`
  branch).
- Agent Link is a thin hub: printing, slicing, printers, cutting, milling,
  fits, threads, mass and print-aware strength moved to Workshop Make;
  standard parts to Workshop Parts; electronics and documents to Workshop
  Electronics and Documents; the OrcaSlicer bridge to Agent Link for
  OrcaSlicer; checkpoints, recovery, the settings log and macros to
  SafetyNet; texture tools to Texturizer; building-code checks to a separate
  add-on. Each keeps its own repository and licence.
- AddonKit is retired: Agent Link carries its own records, shapes, data
  loader, CalculiX reader and sheets.
- Shared argument and refusal helpers (`picks`, `protocol.bad`, `paths`)
  replace many per-tool copies; refusals keep each tool's own words.
- The server reports version 0.3.0, as `package.xml` does.
- `freecadmin` is 1.0.0, the oldest FreeCAD CI runs; 1.1 is recommended,
  as the README and the setup check say.
