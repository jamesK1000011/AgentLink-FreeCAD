# Porting add-ons to Agent Link (design, 18 Nov 2026)

Status: built on main. Written in ASD-STE100.

## Goal

A person has a FreeCAD add-on. The add-on has no Agent Link tools.
Give the person and the agent three things:

- A. A porting guide that `guide_read { topic: "porting" }` reads.
- B. A scaffold. It reads an installed add-on and writes a draft port.
- C. Cookbooks. A cookbook is data: entries that run the add-on through
  the runners that exist.

## A. The porting guide

File: `agentlink/guides/porting.md`. The guide index finds it. No code.
The guide has these sections:

1. Start here (the order of the work).
2. The hook file (`agentlink_families.py`, the family module).
3. The tool data (`tools.json`, the fields, the format check).
4. STE rules (20 words or fewer in a sentence, one instruction a sentence).
5. Refusals (a code and a message with the next step).
6. The core (no `agentlink` import in the add-on's core).
7. Tests (alone, with Agent Link, the import check, the lint).
8. The privacy check (no names, no home paths, no secrets).
9. Cookbooks (when a cookbook is enough, and when a port is better).
10. Agent brief (a block of text to give to another agent).

The guide names no add-on. `tests/test_no_addon_names.py` checks this.

## B. The scaffold

Code: `agentlink/porting.py`. Plain Python, no FreeCAD, no Agent Link
import. It runs in three ways:

- The tool `port_scaffold { folder, name?, overwrite? }`.
- `python3 -m agentlink.porting <folder>`.
- `python3 <hub>/agentlink/porting.py <folder>`.

It reads the add-on's Python files as text with `ast`. It never imports
and never runs the add-on's code. It finds each `Gui.addCommand(name, obj)`
and the `GetResources` of the command's class (`MenuText`, `ToolTip`).

Output: `~/AgentLink/ports/<name>/` only. The scaffold refuses an output
folder inside the add-on or inside Agent Link. It writes:

- `README.md`: what is there and the next steps.
- `hook/agentlink_families.py` and `hook/fam_<group>.py`: the hook.
- `hook/data/tools.json`: one draft entry for each command.
- `hook/api.py`: the core stubs (no `agentlink` import).
- `tests/test_port.py`: the format check, the handler check, the import
  check and the lint.
- `scripts/ste_lint.py`: the lint, plain Python.
- `cookbook.json`: a draft cookbook with one command recipe a command.

## C. Cookbooks

One file for each add-on: `~/AgentLink/cookbooks/<name>.json`.

```json
{"cookbookVersion": "1.0.0", "name": "mine", "about": "…",
 "addon": {"package": "mine"},
 "entries": {
  "mine_do": {"description": "…", "recipe": {"command": "Mine_Do"}},
  "mine_fit": {"description": "…", "recipe": {"python": {"module": "mine.api",
    "function": "fit", "args": {"type": "object", "properties": {"gap": {"type": "number"}}},
    "document": true}}},
  "mine_steps": {"description": "…", "recipe": {"script": {"calls": [
    {"tool": "session_state", "arguments": {}}]}}}}}
```

The runners:

- `command`: `cmd_run { name, index }`, with all of its refusals.
- `python`: the function `module.function(**args)`. The module must be the
  add-on's package or a module in it.
- `script`: a list of Agent Link calls, run by `batch` with rollback.
  `file` names a JSON file in the cookbook's own folder.

The tools (group `porting`, not lean, not in the static base):
`cookbook_list`, `cookbook_show`, `cookbook_import`, `cookbook_export`,
`cookbook_approve`, `cookbook_unapprove`, `cookbook_run`.

### Approval

- The store is the approved-macros store: `~/AgentLink/macros-approved.json`.
  A cookbook key is `cookbook:<name>`. A macro name cannot hold `:`.
- The hash is SHA-256 of the cookbook file and of each script file it
  names, in name order.
- `cookbook_approve { name }` shows the OK dialog in the FreeCAD window.
  The person presses Approve there. No tool can press it, and a typed
  confirm is not taken (red team, 2026-11-18: an agent could type the
  words itself). Headless, the OK is refused. See `agentlink/person_ok.py`.
- A changed file (hash mismatch) needs the OK again.
- An unapproved or changed cookbook: `cookbook_list` lists its entries.
  `cookbook_run` refuses each entry with the next step.
- No entry runs code without the OK. Command recipes also need the OK.

### Against the red team

| Attack | Defence |
|---|---|
| Code runs without an OK | Every recipe kind needs the OK. The check is in `cookbook_run`, before the runner. The OK is a press in the window that no tool can make (`agentlink/person_ok.py`). |
| Approval bypass | The hash covers the file and its script files. A script call to a `porting` tool, to `batch`, to `job_start` or to a tool name with `approve` is refused. Writes by tools to the store or to the cookbooks folder are refused (`paths.check`). |
| Path escape | Names match `^[a-z][a-z0-9_]{1,47}$`. A script file must be in the cookbook's folder after `realpath`. Import reads files only next to the source file. |
| Prompt injection | Descriptions are data. They are capped at 400 characters, one line, no control characters. Answers mark them as the author's words. |
| Name takeover | Entries are never tools. An entry name equal to a tool name is refused on import and refused on run. A cookbook name that is there already needs `overwrite: true`, and then the OK again. |
| Module reach | A python recipe's module must be in the add-on's package. The package must not be a standard library module, `agentlink`, or FreeCAD's own. The package must be in a Mod folder (an installed add-on, not site-packages). Function names that start with `_`, and names of an OK (approve, grant, confirm), are refused. |
| Size | A file holds 256 KB or less, 200 entries or less, 100 script calls or less. |

### Cost

The base listing does not change. The new tools are in the `porting` group.
This group is not lean. With no cookbook installed, nothing more is read
at start.
