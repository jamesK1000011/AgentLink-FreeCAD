# Usage log and progress notifications (18 Nov 2026)

Decided on 18 Nov. Code: `agentlink/usage.py`, `agentlink/protocol.py`.
Tests: `tests/test_usage.py` (classes `Log` and `Progress`).

## 1. Purpose

The usage log shows how agents use Agent Link. Use it to find faults in tools,
descriptions and searches. The log stays on this computer. Agent Link never
puts the log into a normal answer. The agent reads a summary only when it asks:
`usage_report { log: true }`.

## 2. Where the log is written

- Every `tools/call` goes through `Server.call` (`agentlink/protocol.py`). The
  meter (`usage.Meter`) writes one row for each call there.
- The window writes a row for a call that it refuses before the call runs
  (`gui_link._meter_refused`).
- File: `~/AgentLink/usage/<YYYY-MM-DD>.jsonl`. One file for each day.
- Rotation: a file older than 60 days is removed (`usage.prune`, at the start
  of each session and on each read). A day file stops at 20 MB.
- `AGENTLINK_USAGE=off` stops the log.

## 3. Rows

| kind | When | Fields |
|---|---|---|
| `job` | A job starts | `job`, `why` (`start`, `initialize`, `pause`), `mode` (`window` or `headless`), `agentlink`, `freecad`, `addons` (name: version) |
| `call` | Each call | see 3.2 |
| `dialog` | A dialog goes away | `title`, `text`, `buttons`, `by`, `secs`, `blocked`, `job` |
| `list`, `amend` | As before | unchanged |

### 3.1 Job number

- A job is one task of the agent. Its id is `<session>-j<n>`.
- A new job starts at the first call of the session, on `initialize` (a new
  conversation), and on the first call after a pause of 10 min (`JOB_GAP`).
- Each call in a job has a step number `n`.
- Each batch in a job has a batch id `<job>-b<k>`. The batch row lists its
  steps (tool names only, 40 at most).

### 3.2 Call fields

| Field | Meaning |
|---|---|
| `job`, `n` | Job id and step number |
| `gap` | ms from the end of the previous call to the start of this call |
| `grp` | The tool's group |
| `in`, `out` | Characters of the arguments and of the answer |
| `bytes`, `tok` | Bytes of the answer, and estimated tokens (3.5 characters for each token) |
| `img`, `imgs`, `imgBytes` | Picture tokens, picture count, picture bytes |
| `ms` | Time of the call |
| `err`, `why` | Error code, and the reason (cleaned, 160 characters at most) |
| `retry` | The same tool again within 120 s, with changed arguments |
| `find` | `tool_find` or `tool_groups { find }`: the words and the hit names |
| `groups` | `tool_groups` enable or disable lists |
| `undo` | `undo`, `redo` or `restore` (the `history_` tools) |
| `steps`, `batch`, `rollback` | A batch: its steps, its id, and the count of steps undone by its rollback |
| `background` | The call gave its work to a background job: the job id |

### 3.3 Dialogs

The window's heartbeat tells the meter which dialog is in front. When the
dialog goes, the meter writes one row:

- `by`: `agentlink` (the dialog rule of Agent Link, or the supervisor),
  `agent` (`dialog_answer`), or `person` (all other cases).
- `secs`: the time the dialog held the window.
- `blocked`: the calls that the window refused while the dialog was up.

### 3.4 Watchdog stops

The supervisor writes its events to `~/AgentLink/watchdog.log`. The log report
reads that file and counts the events (for example `hang`, `force_restart`,
`dialog`). The usage log does not copy them.

## 4. Privacy

- The log never keeps argument values. It keeps a hash of the arguments in
  memory only, to find a retry.
- The log never keeps file contents or document geometry.
- Text (reasons, dialog text, search words) goes through `usage.clean`:
  - A path in the user folder becomes `~/...`.
  - All other absolute paths become `<path>`.
  - The text is cut to 160 characters.
- The test `Log.test_rows_marks_and_report` checks that no argument value and
  no full user path is in the file.

## 5. The report

`usage_report { log: true, days: 7, jobs: 8 }` gives:

- `lastJobs`: for each job, the mode, versions, steps, calls, errors, retries,
  time, tokens and the sequence of tools.
- `errorsByTool`: count, codes and the three most frequent reasons.
- `retries`: count, count after an error, tools.
- `toolFind`: searches, searches whose hit was then called (`usedRate`), and
  five searches without use.
- `groupSwitches`, `undos`, `rollbacks`, `background`, `dialogs`, `watchdog`.
- `gapMs` (median, p90, max), `answers` (bytes, tokens, largest by tool),
  `pictures`.

The report is only in this answer. Other answers do not change.

## 6. Progress in chat

- The echo writes each step's text in the status bar (`echo.say`). The same
  text goes to the client as `notifications/progress`.
- Agent Link sends it only when the request gives
  `params._meta.progressToken`. `progress` counts up from 1 in each call.
- A notification is a message of its own. It adds no tokens to the answer.
- Headless: `server.py` writes the notification at once. Window: the link
  writes it on the call's own connection, until the call is answered.

  does not show them, the batch `title` must say what the batch does.

## 7. Token bounds in the tests

`tests/test_needs.py` no longer fails on a total (all tool definitions, or the
lean listing). It prints the totals and the change from the last measured
values. The bounds on one piece stay: the largest card, the `tool_groups` card,
the pushed line and the replies. The test fails if the count of tools goes
down.
