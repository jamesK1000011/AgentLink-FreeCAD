# Part workbench hardening: findings (agent "part", 16 Nov 2026)

Checkout: the agent checkout. Nothing was run on FreeCAD here (not installed): every fix is from reading FreeCAD 1.1's source, and every "live check" below is unproven until the Mac runs it. `python3 -m pytest -q -x`: 676 passed, 242 skipped (the FreeCAD ones).

Counts: 32 tools checked (27 in group model, 5 Part tools in std_more); 32 descriptions rewritten; 25 behaviour fixes across 14 tools (listed per tool, marked FIXED); refusals reworded in all four files. Descriptions total 10,815 → 14,416 characters (1.33x): the model.py ones grew 1.18x (part_loft was cut from 2,457 to 1,595), the short ones in model_more / part_more / std_more grew more because they named no gotchas or reply fields at all.

## Things that cut across tools

- **How these tools work.** Only primitives, wires, split, join, compound, compound filters, ruled, section-with-a-body, Offset2D (open wire or face) and datums make FreeCAD feature objects. Booleans, fillets, chamfers, offset, shell, extrude, revolve, loft, sweep, mirror, scale, arrays, refine, fix and defeature call the shape methods (`Shape.fuse`, `makeFillet`, `makeThickness`, `extrude`, `Part.makeLoft`, `makePipeShell` …) and store a plain Part::Feature. So Part::Fillet's `Edges` tuples, Part::Extrusion's `DirMode / LengthFwd / TaperAngle`, Part::Offset's `Mode / Join / Fill`, Part::Loft's `Linearize`, and the 1.x boolean `Refine` property are never set by these tools. I read those feature sources to check the shape calls take the same arguments (they do) and wrote "done on the shape, not as a Part::X feature" into the descriptions and the guide, since an agent that expects an editable Fillet object will be wrong.
- **Jobs.** The brief asks heavy tools to point at jobs. agentlink/jobs.py runs reads only ("never a change"), and every tool here changes the document, so none can be a job. The descriptions and guide say the limits and the first-call estimate instead (part_boolean, part_loft through keep.SIZED), and the guide's new "Heavy steps" section says jobs do not apply.
- **Refusals roll back.** tools.py aborts the transaction on any ToolError, so "nothing was kept" holds even where a tool raises after making an object. View-side visibility is not in the transaction, so I moved the two hide-the-input lines to after success (compound_filter, part_join).
- **BOPTools and CompoundTools makers use `FreeCAD.ActiveDocument`** (SplitFeatures.makeSlice / makeBooleanFragments / makeXOR, JoinFeatures.makeConnect / makeEmbed / makeCutout, CompoundFilter.makeCompoundFilter without `into_group`). The session's document is `session.doc`, which is not always the active one. FIXED in part_split, part_join and compound_filter by building the Part::FeaturePython in `session.doc` with the same proxy and view-provider classes the makers use.
- **Wish for health.py / keep.py (not edited):** part_from_mesh is in neither keep.HEAVY nor keep.SIZED, so a 50,000-triangle mesh gets no estimate and no longer watchdog deadline; its only limit is maxFacets (60000). I have no measured time to put in the description, so it says "slow" without a number. Worth timing on the Mac and adding to SIZED by facet count.
