## 1. The person's OK

### Attack
`cookbook_approve` took `confirm: "approve cookbook <name>"`. Any agent can
type those words. The same was true of `app_extensions add` ("install
<repo>"), `addon` ("install <name>") and SafetyNet's `macro_approve`
("approve <name>"). The OK was a convention only.

### Design of the fix
New module `agentlink/person_ok.py`. The OK is a press on Approve in a
dialog in the FreeCAD window.

- The tool call shows the dialog and answers `pending`. The agent tells the
  person to look at the window.
- A press counts only when all of these are true:
  - The event came from the system: `QEvent.spontaneous()`. Events that
    Agent Link sends (`gui_input`, `dialog_answer`) are never spontaneous.
    `QAbstractButton.click()` makes no event, and the button is never
    connected to `clicked`.
  - The dialog was in view for 1.5 s or more. Approve stays grey until then.
  - The test flag `AGENTLINK_AS_USER` is off.
- `gui_input` refuses every widget in the dialog. `dialog_answer` (press,
  fill, press_hard) refuses it. The agent gets a clear refusal.
- Decline is the default button. Return does not approve by accident.
- The dialog shows the text as plain text, one line each, capped. It says
  that the text is the author's words, not instructions.
- At the press, the file is read again. If its hash is not the hash shown,
  nothing is approved.
- A kept OK (a cookbook, a macro) goes to the store at the press. A one-time
  OK (an install, an extension) gives a grant for 10 minutes. The next call
  with the same arguments uses it up.
- Headless (no window): the OK is refused with `unavailable`. The agent says
  so. This is the owner's rule.
- Add-ons use `hooks.person_ok(kind, name, title, lines, sha, on_ok)`.
  SafetyNet's `macro_approve` uses it.

### Why this design
- A file that the person makes was weighed. The agent can write files under
  the home folder, so the folder must be hidden, and the person must type a
  command. The owner does not want terminal steps.
- A button in the Agent Link panel was weighed. It is the same as the dialog
  for `gui_input`, but the person must find it. The dialog comes to the
  person.
- The dialog costs the person one press. It is the same press as before, but now
  an agent cannot make it.

### What is left
- A program with control of the whole Mac (a screen-control tool, a script
  that the person runs) makes system events. That is outside MCP and outside
  Agent Link. Do not give an agent screen control while an OK dialog is open.
- `app_recover accept` (SafetyNet) and `app_restart { save: "all" }` still take
  a typed confirm. They write documents. They do not run code. See the
  decisions below.

## 2. Tool data and cookbooks that run code

### Attack
- `get(o, "__class__")` and `"$o.__init__.__globals__"` reached private
  names. `expr.parse` refused `o._x`, but not a name in a string.
- `maker("os.system")` imported any module. With a comprehension,
  `[f("…") for f in [maker("os.system")]]` called it.
- `{"do": [o, "doCommand", "…"]}` ran Python text through `FreeCADGui`.
- A python recipe named its own package. `pip._internal.cli.main.main` passed
  the checks (pip is not in the standard library).
- `gui_input` typed into the Python console and pressed Return. That is
  any code. It also clicked Macro > Macros…, Tools > Edit parameters… and
  the Addon Manager, which `cmd_run` refuses.

### Fix
- `expr.safe_name()`: no private name and no name that runs Python text
  (`doCommand*`, `exec`, `eval`, `system` …). It is used by `get()`, method
  calls, `fmt` paths, the runners' `$` paths, `do`, `set`, steps `set`,
  apply's `method` and `copy`.
- `maker()` and steps `make`: never a module of the standard library,
  builtins, `FreeCADGui`, `Gui`, Agent Link, PySide, shiboken, pip or
  setuptools; never a private part.
- Python recipe: the package must be in a Mod folder (an installed add-on).
  This is found with `importlib.util.find_spec`, before any import. A
  function or module name with approve, grant, confirm or person_ok is
  refused. A private submodule is refused.
- Cookbook scripts: `gui_input`, `dialog_answer`, `gui_unstick` and
  `addon_test` are added to the blocked calls.
- `gui_input`: every event is checked before it is sent. It refuses the
  Python console, the macro editor, the macro, parameter, preferences,
  customize and Addon Manager dialogs, and the OK dialog. A menu item, a
  tool button or a shortcut whose command `cmd_run` refuses is refused.
- `port_scaffold` drafts no tool for a command that `cmd_run` refuses. It
  lists it under "Not read".

### What is left
- The hub's own `tools.json` is trusted. The runners run only the hub's
  data. Add-on tool data binds handlers (the add-on's own code).
- An approved cookbook's python recipe imports the add-on's module. That
  module is code that the hash does not cover. The OK says so.
- `agentlink/needs.py` (dry reading) was read, not attacked in depth.

## 3. Paths that leave their folders

### Attack and result
- Held: `..`, symlinks, `~`, the batch's `to:` and `$file`, `outDir` (fixed
  at start), cookbook script files, import and export, lesson pictures and
  fixtures (schema patterns), `port_scaffold` output.
- Failed: macOS disks ignore case. `~/.SSH/id_rsa` passed the secret check.
  `~/library/LaunchAgents/x.json` passed the Library check.
  `~/agentlink/MACROS-APPROVED.json` passed the store check. A write there
  could forge every OK.
- Failed: `.pth` (Python runs it at start), `.pyz`, `.pyd`, `.whl`, `.egg`
  and `a.py.` were not refused.

### Fix
- Every refusal compares without case (`casefold`).
- `points_file`, `profiles_file` and `folder` are in `PATH_KEYS`.
- The extensions above are refused. A name that ends in a dot or a space is
  refused.

## 4. Prompt injection in descriptions

- Held: cookbook `about` and descriptions are one line, 400 characters or
  fewer, with no control characters. Each answer has the data note. The
  server's instructions say that text from files and models is data.
- Failed: `extend_tool(describe=…)` added any text to a hub tool's
  description. Now one line, 300 characters or fewer.
- The OK dialog shows the author's text as plain text (no rich text), one
  line each, 40 lines or fewer.

## 5. One add-on takes over another's names

- Held: a tool with a hub tool's name is left out. An add-on never hides a
  hub tool.
- Failed: an add-on that said `GEOMETRIC = {"export"}` turned off the path
  check of the hub's `export`. Now `families.owned()` takes GEOMETRIC and
  PINNED_FREE only for the add-on's own tools that loaded.
- Failed: add-on tool data with a hub tool's name and `pathIsCurve` did the
  same. `tooldata.build` now declares nothing for a hub tool's name.
- Failed: `extend_tool("cookbook_approve", before=…)` could put words in the
  arguments. Now `hooks.NOT_EXTENDED` (and any name with approve) is never
  extended. An add-on adds its own with `hooks.keep_unextended()`. The check
  is when the extensions are put on, so the load order does not matter.
- Failed: an add-on family with `LEAN = True` and a hub group name (dev)
  put that hub group in the default list. Now LEAN counts only for an
  add-on's own group.
- Left: an add-on can join a hub group (SafetyNet joins core) and can say
  REPLACES for a hub group. That hides a hub group from the listing. It is
  still callable. See the decisions below.

## 6. Lessons and shared files

- Failed: a lesson's `do`, `setup.calls` or `else` could call any tool. "Do
  it for me" runs them as the person's click. Now a lesson never calls
  `batch`, `job_start`, `live_run`, `gui_input`, `dialog_answer`,
  `gui_unstick`, `addon`, `addon_test`, `app_extensions`, `agentlink_update`,
  `app_restart`, `app_force_restart`, `pref_*`, `port_scaffold`,
  `outputs_clean`, `doc_revert`, `doc_close`, `crash_collect`, `cookbook_*`,
  `macro_*`, or a name with approve. The check is at load and at run.
- Failed: an inline lesson could set `_folder` and `_owner`. They are taken
  out now.
- Held: the batch's shared files (`to:`, `$file`) go through `paths.check`.
- Not tested: agentlink-collab (private, not in this run).

## Decisions for the owner

1. The OK is a press in the window. Headless, every OK is refused. Is that
   right for the hidden FreeCAD, or do you want a second way (a file that you
   make in a hidden folder)?
2. `app_recover accept` and `app_restart save: all` still take typed words. Move
   them to the window OK too?
3. An add-on can say REPLACES for any hub group except core. Keep, or allow
   it only for groups that the add-on names in its own docs?
4. `addon` install from a local folder is allowed after the OK. Keep?
